# Zenodo Release Checklist

- Confirm the GitHub repository is organized and documented.
- Decide whether the repository stays private until article acceptance.
- Remove files that are large, redundant, or not needed for reproducibility.
- Create a tagged release in GitHub, for example `v1.0.0`.
- Make sure `README.md` and `CITATION.cff` are final before the release.
- Connect the GitHub repository to Zenodo.
- Verify that Zenodo captures the release and mints a DOI.
- Add the DOI to the manuscript, supplementary information, and repository README.
- If raw trajectories are too large for GitHub, deposit them separately and link them from the README.
